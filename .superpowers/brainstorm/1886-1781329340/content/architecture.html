3D八重樱 — 架构方案对比

核心体验：3D角色 + LLM流式对话 + TTS语音合成

A

单体 Unity 架构

全部在 Unity C# 中实现：HttpClient 调 LLM API (流式)、WebSocket 连 GPT-SoVITS、场景管理、UI (uGUI/UI Toolkit)

优势

  • 单一项目，无外部依赖
  • C# 原生，性能好
  • 打包部署简单

劣势

  • HTTP/WS 需手写
  • 没有现成的记忆系统
  • 调试 LLM 交互不如 Python 方便
B

Unity + Python 桥接

Unity 负责 3D 渲染和 UI，Python 后端负责 LLM API、TTS 连接、记忆系统等所有非渲染逻辑

优势

  • 复用现有 Python 代码
  • 记忆系统直接继承
  • 逻辑和渲染分离清晰

劣势

  • 多进程通信复杂
  • 需要 Python 运行环境
  • 部署复杂度高
C

混合渐进

先在 Unity 中实现 UI + 3D 角色 + LLM 直连 + TTS 客户端，后期需要记忆系统时再通过 localhost HTTP 与 Python 后端通信

优势

  • 起步快，无外部依赖
  • 后期可扩展
  • 当下即可看到效果

劣势

  • 记忆系统需后期加
  • 架构边界需提前设计好
